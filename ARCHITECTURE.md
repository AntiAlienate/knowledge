# Architecture — AntiAlienate Knowledge

This repository is a primary-source knowledge base on parental alienation across jurisdictions, published under CC BY 4.0. Consumers include academic citers, family-law practitioners, public-interest journalism, search-engine indexes, and the Liena RAG ingestion pipeline.

## Single source of truth: JSON

**JSON is canonical. Markdown is rendered.**

Every practitioner directory file and every case study file has a `.json` sidecar conforming to a JSON Schema in `schemas/`. The `.md` sibling is generated by `bin/aa-build render` from that JSON. **Do not hand-edit the `.md`** — your changes will be overwritten on the next build.

This is the single most important architectural rule.

### Why

- One source of truth — no drift between human-readable and machine-readable views.
- Liena RAG (and any future downstream) can ingest structured JSON instead of parsing prose.
- Cross-linking between entities works programmatically.
- Schema validation in CI catches malformed contributions before they ship.
- Aggregate files (`eu.md`, `latam.md`) and coverage indexes are regenerated, not hand-maintained.

## Schemas

### Practitioner (v2.0)

`schemas/practitioner.schema.json`

A practitioner file describes a country's PA-clinical or PA-legal directory. Each `entry` has:

- `id` — `<country_code>.<slug>`, lowercase, hyphen-separated. Stable across the entity's lifetime. Example: `de.zimmermann-walper-fichtner`.
- `stance` — one of `recognition`, `critique`, `middle`, `forensic-evaluator`, `institutional`, `cross-jurisdictional`. Must be primary-source justified in `stance_notes`.
- `urls` — at least one primary-source verification URL.
- `publications` — structured citation records with year + venue + URL/DOI.
- `references` — cross-links to other entities. Format: `<type>:<id>` (see below).

The file also carries `jurisdictional_context` (long prose) and `structural_findings` (bullet list of headline findings — for example, that the institutional critique pole is institutionally anchored vs clinician-anchored).

Excluded entries (regulatory, safeguarding, or unverifiable) live in a separate `excluded` array with `exclusion_reason` and `primary_source_url`.

### Case study (v1.0)

`schemas/case-study.schema.json`

A case study file represents one judicial decision. Required fields:

- `slug` — matches the filename stem
- `caption`, `court`, `decision_date`, `jurisdiction_code`
- `summary` (why this case matters) + `holding` (ratio decidendi)
- `sources` — at least one, with `title` + `url` per source

Optional but conventional:

- `ecli`, `neutral_citation` — formal identifiers
- `panel`, `judges` — bench composition
- `parties` — anonymised per the deciding court's convention. **Never** include identifying info for children. Use the court's anonyms (`Kind 1`, `Mary`, `NF`).
- `counsel`, `experts` — counsel and forensic experts. Use `Sachverständige A` style where the court anonymised them.
- `verbatim_quotes` — every quote with paragraph reference and source URL. Use the verbatim original language; provide `translation_en` separately.
- `comparative_jurisprudence` — pointers to related cases (cross-link to slug if we have a case study)
- `editorial_notes` — what could not be verified from primary text; methodology caveats
- `author` — must be `Alan Markson`
- `license` — must be `CC-BY-4.0`

## Cross-linking

Format: `<type>:<id>`

| Type | ID source | Example |
|---|---|---|
| `practitioner` | `entries[].id` | `practitioner:de.zimmermann-walper-fichtner` |
| `case-study` | `slug` | `case-study:bverfg-1-bvr-1076-23-germany-2023` |
| `jurisdiction` | filename stem under `jurisdictions/` | `jurisdiction:germany` |
| `evidence` | filename stem under `evidence/` | `evidence:alienating-tactics-as-child-abuse` |

`aa-build refs` resolves every `references` entry across the repo. Broken refs fail CI.

## Build pipeline

```bash
# from repo root
python bin/aa-build validate       # JSON Schema validation
python bin/aa-build refs           # cross-link resolution
python bin/aa-build render         # JSON → MD
python bin/aa-build index          # rebuild practitioners/*/README.md
python bin/aa-build aggregate      # mark region-aggregate files as superseded where deepened
python bin/aa-build build          # all of the above
python bin/aa-build urls           # opt-in HEAD-check of every URL (slow)
```

CI runs `validate` + `refs` + `render` on every push to `main` and every PR. The `render` step also acts as drift detection: if a rendered MD differs from the JSON-derived output, the build fails. This forces JSON-edit-then-render rather than direct MD edits.

## Push pipeline

```bash
# single file
python bin/aa-push practitioners/therapists/de.json --msg "therapists: refine Germany Rn.34 quote"

# multi-file
python bin/aa-push \
  practitioners/therapists/de.json \
  practitioners/therapists/de.md \
  practitioners/therapists/README.md \
  --msg "therapists: Germany Rn.34 quote + regenerated README"

# PR-style (branch + manual merge)
python bin/aa-push <files> --branch fix/germany-rn34 --msg "..."
```

`aa-push` reads `GITHUB_TOKEN` from `/tmp/.aa-secrets/gh` by default (override with `--token-file`). It creates the branch from `main` if it doesn't exist. SHAs are printed for traceability.

## Anonymisation rules

The deciding court's convention wins. Specifically:

| Jurisdiction | Convention |
|---|---|
| Germany (BVerfG / OLG) | `Kind 1`, `Kind 2`, or initials only |
| UK (EWFC / Court of Session) | First name pseudonym (e.g. `Mary`) or two-letter (e.g. `NF`) per s.97 CA 1989 + Scottish family-law convention |
| Australia (FCFCOA) | First name pseudonym per FLA s.121 |
| Brazil (TJ) | Initials per LGPD + ECA |
| India (HC/SC) | Initials per Vishakha-line privacy practice |
| Spain (AP) | Initials per LOPJ 232 |

Do not invent identifying details. If a court named a Sachverständige or expert publicly in its decision, that name may stand; otherwise use `Sachverständige A` or `the court-appointed expert`.

## Editorial standards

- **Primary sources required.** Every claim links to either the deciding court's text, official press release, or the official institutional registry. Secondary lit (NJW, NZFam, LTO, FamRZ, Cairn) is fine for context but is marked inline with `[NZFam 2026, X]` or `[Pressemitteilung]`.
- **Verbatim quotes in original language**, with English translation in parentheses. Never paraphrase as if verbatim.
- **"Not publicly confirmed" / "not verifiable"** beats a guess. The verification_notes field captures what was checked vs. what wasn't.
- **Both camps must be represented.** If a jurisdiction's critique camp is institutionally thin, say so explicitly in `structural_findings`.
- **Exclusions are documented, not silenced.** Regulatory/safeguarding/unverifiable exclusions go in the `excluded` array with `exclusion_reason` and a `primary_source_url`.

## Adding a country (practitioners)

1. Create `practitioners/<type>/<country_code>.json` with `schema_version: "2.0"`.
2. Populate `country`, `country_code`, `type`, `license: CC-BY-4.0`, `generated`, `jurisdictional_context`.
3. Add entries with stable IDs (`<country_code>.<slug>`).
4. Each entry: stance + stance_notes + at least one URL + (if academic) publications array.
5. `python bin/aa-build validate` — must pass.
6. `python bin/aa-build render` — generates the `.md` sibling.
7. `python bin/aa-build index` — refreshes the README coverage table.
8. `python bin/aa-push practitioners/<type>/<country_code>.json practitioners/<type>/<country_code>.md practitioners/<type>/README.md --msg "..."`.

## Adding a case study

1. Create `case-studies/<slug>.json` conforming to `case-study.schema.json`.
2. Required: caption, court, decision_date, jurisdiction_code, summary, holding, at least one source, author, license.
3. Anonymise children per the court's convention.
4. Include verbatim quotes with paragraph numbers + source URL.
5. Add comparative jurisprudence with `case_study_ref` cross-links where we have the matching slug.
6. `aa-build validate` then `aa-build render`.
7. `aa-push case-studies/<slug>.json case-studies/<slug>.md --msg "..."`.

## What was wrong before this refactor

The pre-refactor state (recorded for fleet posterity):

1. JSON and MD were parallel-maintained — drift was inevitable.
2. Case studies were `.md` only — Liena RAG couldn't ingest them as structured data.
3. No cross-linking schema — a case study mentioning a practitioner had no programmatic link.
4. No schema validation, no link checking, no duplicate-ID detection — quality decayed silently.
5. Region-aggregate vs. country-deepened relationship was ambiguous — `eu.md` had 22 entries while `de.md` had 16, and there was no marker explaining which was authoritative.
6. No per-file license header — single-file copies lost attribution.
7. Eight near-identical `push-X.py` scripts in `/tmp/` — every new push grew the maintenance surface.
8. Every push went straight to `main` — no preview, no review.

The current architecture addresses 1–7. PR-workflow enforcement (#8) is supported by `aa-push --branch` but not yet required.

## Future work (open to claim)

- Convert all existing practitioner files from `schema_version: "1.0"` MD-with-sidecar to v2.0 JSON-source-of-truth. Migration is mechanical.
- Convert all existing case studies (27+) to dual MD+JSON.
- Add `aa-build urls` to CI on a weekly cron (vs. every-push — link rot is non-blocking).
- PR-required workflow: GitHub branch protection on `main`; `aa-push --branch` becomes mandatory.
- License footer is currently injected in rendered MD only; raw `.md` files in `jurisdictions/` and `evidence/` need a one-shot pass to add headers.
